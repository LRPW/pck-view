## Работа с проектом

1. Нажмите **Создать проект**, укажите папку клиента и выберите архивы для импорта.
2. PW Forge скопирует папку `data` и выбранные PCK/PKX в проект. Манифест `.pwforge` можно открыть из приложения или
   двойным щелчком после регистрации через **Ассоциация .pwforge**.
3. Открывайте ресурсы в дереве слева. Они появляются во вкладках справа. Записи архивов индексируются, а содержимое
   извлекается в кэш при открытии файла.
4. Сохранённые правки хранятся отдельно от исходных файлов. Сборка проекта создаёт изменённые PCK и отдельные файлы для
   переноса в клиент.

Кнопка **Открыть** также позволяет открыть отдельный архив или файл клиента без проекта.

### Импорт и сборка

- При создании проекта можно выбрать архивы, версию клиента и профиль схемы `elements.data`. Импорт серверных файлов выполняется отдельно через меню **Инструменты**.
- В проекте **Сохранить** записывает изменения в слой правок. Для открытого отдельно архива доступна команда **Сохранить PCK как…**.
- **Полная сборка** формирует полный комплект проекта. **Сборка изменений** выводит изменённые архивы и отдельные файлы. Результаты находятся в `builds/`; старые сборки можно очистить из меню **Инструменты**.
- В настройках доступны русский и английский языки, светлая, тёмная и системная темы, переназначение горячих клавиш и настройка числа потоков сборки.

## Формат проекта на диске

```text
MyProject/
  MyProject.pwforge
  originals/
    data/
    archives/
  edits/
    data/
    archives/<архив.pck>/<путь ресурса>
  .forge/
    index/<архив.pck>.json.gz
    cache/
    backups/
  locales/
    source.json
    ru.json
  builds/<идентификатор сборки>/
    pwforge-build.json
```

Манифест представляет собой JSON с `format: "pw-forge-project"` и `version: 2`. Поля `name`, `source`, `archives`,
`status` и `errors` описывают имя, исходную папку клиента, выбранные архивы, состояние и ошибки импорта. `bug.pck`
исключается. Файлы проекта обслуживаются относительно каталога манифеста.

При чтении приоритет имеет соответствующий файл в `edits/`. Если правки нет, обычный файл читается из `originals/data/`,
а ресурс архива извлекается из PCK/PKX. Индекс версии 2 хранит имя, смещение, распакованный и упакованный размеры
записей. Сохранённый индекс переиспользуется при совпадении метаданных PCK и PKX. Изменение архива или отсутствие
индекса приводит к повторному чтению таблицы записей. Каталоги `.forge/index/` и `.forge/cache/` воспроизводимы из
исходных копий.

Сборка принимает сохранённые правки из `edits/`, группирует ресурсы по архивам и создаёт только затронутые PCK и
отдельные изменённые файлы. Результат сначала записывается во временный каталог, затем публикуется в `builds/`. В
`pwforge-build.json` перечислены собранные архивы и количество отдельных файлов. При необходимости архив проекта
разделяется на PCK и PKX.

## Редакторы и поиск

| Формат | Возможности |
| --- | --- |
| PCK / PKX | Дерево ресурсов, извлечение, добавление, замена, удаление и упаковка |
| `elements.data` | Категории, поиск записей, типизированные поля, выбор и предпросмотр ресурсов |
| `gshop.data`, `gshop1.data`, `gshop2.data` | Категории и подкатегории, слоты покупки, иконки инвентаря, переход к связанным записям |
| `domain.data`, `domain2.data`, `domain2_cross.data` | Карта, список территорий и подсветка соседних областей |
| `tasks.data` | Дерево заданий, поля, награды, тексты, диалоги и существующие подзадания |
| `dyn_tasks.data`, `task_npc.data` | Редакторы динамических заданий и записей NPC заданий |
| `aipolicy.data` | Дерево политик ИИ, условия и действия |
| `extra_drops.sev`, `npcgen.data`, `path.sev`, `wmgj.nmd` | Серверные записи, выбор секции, переход по номеру или ID и редактирование полей |
| XML-интерфейсы | Визуальный редактор, дерево элементов и панель свойств |
| `DCF`, `STF`, `HTF`, `DTF` | Реестр окон и редакторы старых форматов интерфейса |

Из редакторов магазина и заданий можно перейти к связанным записям предметов и NPC, если в проекте доступен соответствующий `elements.data`. Из `world_targets.txt` и `serverlist.txt` можно экспортировать бинарные `world_targets.sev` и `serverlist.sev`.

### Версии elements.data

Редактор определяет версию по заголовку и подбирает схему из каталога. В настройках проекта можно выбрать версию и вариант вручную. Доступны 94 профиля для 90 версий, включая отдельный профиль LRPW для v145.

```text
6–7, 10, 12–15, 17–18, 20, 22, 24–25, 27, 29–33, 52–56,
60–63, 65–70, 73, 76–77, 80–81, 84–85, 87–88, 99–102,
104–106, 108, 112–115, 118, 120–125, 127–137, 144–145,
153–157, 159, 161–162, 164–165, 167–170, 181
```

### Версии tasks.data

Версия определяется по заголовку файла и отображается в редакторе. Доступны схемы 108 версий формата.

```text
43, 52–57, 59–60, 63–64, 68–69, 75, 78–130,
135, 137, 139–140, 146–147, 153, 156–158, 161–164, 167,
175–178, 180–183, 185–195, 198, 215–220
```

Поля, от которых зависит структура записи, защищены от прямой правки. Подзадания редактируются в существующем дереве. Чтение и сохранение для перенесённых схем проверены на синтетических файлах. Проверка на реальных файлах охватывает не все версии. Схема перенесена из MyAceEditor по [GPL-3.0](src-tauri/src/task_schema_generated.LICENSE).

### Версии других форматов

| Формат | Поддерживаемые версии и варианты |
| --- | --- |

| `dyn_tasks.data`, `task_npc.data` | v10 и v1 соответственно |

| `path.sev` | v0–v1 |
| `wmgj.nmd` | NMD v1 |


### Редактирование интерфейсов

- В XML-редакторе можно выбирать элементы на холсте и в дереве, менять размеры и свойства, переставлять элементы и менять их родителей. Для flex-контейнеров доступны направление, выравнивание и размер по содержимому.
- Предпросмотр использует доступные игровые текстуры и шрифты. Исходный XML открывается в текстовом режиме.
- В DCF можно добавлять и удалять записи окон, менять координаты и видимость при запуске, открывать связанный XML. Редактор отмечает дубликаты и отсутствующие XML.
- Для STF, HTF и DTF доступны отдельные редакторы. У DTF также есть визуальный режим.

### Поиск по содержимому

Поиск открывается в отдельном окне, которое можно перенести на второй монитор. Область поиска можно ограничить проектом, модулем PCK/data или папкой. Доступны маски файлов, регулярные выражения, учёт регистра и поиск целых слов. Отмена сохраняет уже найденные совпадения.


## Предпросмотр и экспорт моделей

- Для обычных ресурсов доступны просмотр изображений, декодирование DDS/TGA, воспроизведение аудио и видео, текстовый и HEX-режимы.
- Нативный компонент Angelica проигрывает поддерживаемые `.gfx` и показывает модели `.mox`, `.ecm`, `.smd`, `.ski` и скелеты `.bon`. Для моделей доступны вращение и масштабирование камеры. Анимацию можно поставить на паузу или запустить заново.
- Для ECM и SMD можно выбирать объявленные в модели действия. SKI требует BON с тем же базовым именем. Нативный просмотр читает исходные архивы с диска, поэтому для него важны доступные архивы с текстурами, конфигурацией и шейдерами.
- Экспорт GLB сохраняет геометрию MOX. Для поддерживаемых ECM, SMD и SKI в GLB также включаются скелет, веса, объявленные анимации и диффузные текстуры. Морфинг, ткань и игровые шейдеры не переносятся. Подробности и ограничения перечислены в [документации нативного компонента](native-gfx/README.md).

Выбор анимации использует треки, объявленные в модели. Произвольный внешний STCK подключить нельзя. Совместимость GFX зависит от ресурсов и версии клиента. Нативный предпросмотр и захват PNG интерфейса через MCP используют разные механизмы, поэтому нативные GFX в такой PNG не попадают.

## Перевод

Экспорт текстов создаёт `locales/source.json`. Записи содержат путь к файлу, путь к полю и отдельные фрагменты текста с
цветами. Перевод хранится в файле выбранной локали, например `locales/ru.json`.

- В редакторе можно искать текст, показывать только пустые строки и переводить их вручную или пакетно.
- Поддерживаются DeepL, Yandex Translate, Ollama и OpenAI-совместимые API. Ключи сохраняются в Диспетчере учётных данных
  Windows.
- Пакетный перевод показывает сохранённые результаты по мере обработки. Его можно отменить и продолжить. Заполненные
  фрагменты сохраняются, а изменения плейсхолдеров и кодов разметки помечаются для ручной проверки.
- **Применить перевод** записывает изменения в файлы проекта через слой правок, сохраняя цвета и исходные файлы.

### Структура JSON

Исходный каталог содержит массив `entries`. Файл перевода также содержит `version` и `language`. В каждой записи `file`
задаёт виртуальный путь, `path` указывает поле внутри ресурса, а `segments` содержит фрагменты с `text` и `color`. Цвет
записывается как шестизначный RGB без префикса или как `null`. Запись перевода может содержать `source_segments` для
сверки с исходным текстом.

Во время пакетного перевода готовые фрагменты записываются в журнал `<язык>.pending.jsonl`. При завершении или следующем
запуске пакетного перевода журнал объединяется с JSON локали, заполняя пустые фрагменты. При применении проверяются
исходные сегменты и пути полей. Ошибки возвращаются пофайлово.

## Локальный MCP-сервер

Запустите `pwforge.exe --mcp` как локальный stdio-сервер. Клиент MCP может открыть проект `.pwforge`, создать новый проект из файлов клиента или работать с отдельным PCK. Для отдельного архива нужно указать путь к новому выходному файлу.

- Для интерфейсов доступны поиск XML, чтение дерева, правки координат и размеров по ревизии и захват PNG предпросмотра. Для захвата нужны Node.js 22+ и Chrome или Edge.
- Для игровых данных доступны просмотр, замена и поддерживаемые структурированные правки. Можно экспортировать каталог текстов и передать переводы обратно в проект.
- В проектном режиме команда сохранения пишет в тот же слой правок, который использует настольный редактор. Сборка создаёт выходной архив или результат сборки проекта.

Примеры подключения и параметры инструментов приведены в [MCP.md](MCP.md).

## Устройство приложения

- `src/app/IdeApp.tsx` управляет деревом, вкладками и открытием ресурсов.
- `src/features/editor/` содержит редакторы, `src/features/search/` — отдельное окно поиска.
- `src-tauri/src/project.rs` отвечает за импорт, индексы, слой правок и сборку проекта. `ide.rs` обслуживает ресурсы и
  отдельные файлы.
- `src-tauri/src/locales.rs`, `locale_batch.rs` и `translation.rs` отвечают за локали, пакетную обработку и запросы к
  провайдерам.
- `native-gfx/` содержит отдельный исполняемый компонент. Tauri запускает его для нативного предпросмотра и
  взаимодействует с ним через бэкенд.

## Установка и сборка

Запустите установщик или распакуйте ZIP из [релизов](https://github.com/LRPW/pw-forge/releases) в отдельную папку и
запустите `pwforge.exe` рядом с `native-gfx.exe` и DLL. Для запуска нужен WebView2 Runtime.

Для сборки нужны Node.js, Yarn Classic, Rust с MSVC, Visual Studio с инструментами C++ x86, Windows SDK и DirectX SDK
June 2010. Native GFX также использует исходники и библиотеки движка из дерева клиента, описанные
в [native-gfx/README.md](native-gfx/README.md).

Из каталога с `package.json`:

```powershell
yarn install --frozen-lockfile
npm run tauri dev
```

Команда `npm run tauri:build` собирает portable ZIP, установщик NSIS, подпись установщика и `latest.json` в `release/`.
Native GFX собирается автоматически.

Для обновлений загрузите установщик, portable ZIP, подпись и `latest.json` в GitHub Release с тегом
`v<версия из package.json>`. Установленное приложение проверяет и устанавливает обновления через «Справка → Проверить
обновления». Portable-сборка открывает страницу релиза для загрузки ZIP.

Локальная сборка создаёт ключ в `.release-signing/update.key`. Повторные релизы подписывайте тем же ключом. Для внешней
сборки передайте `TAURI_SIGNING_PRIVATE_KEY` и соответствующий публичный ключ в `PW_FORGE_UPDATE_PUBLIC_KEY`. Для
защищённого ключа также задайте `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

```powershell
npm test
cargo test --manifest-path src-tauri/Cargo.toml
```

Для интеграционных тестов с реальными файлами задайте `PW_CLIENT_DIR` на папку установленного клиента и запускайте
нужный тест с `-- --ignored`.

## Ограничения PCK

Поддерживается формат `0x20002`, включая разделённые архивы PCK/PKX. Отдельный архив в настольном редакторе сохраняется в один PCK размером меньше `0x7fffff00` байт. Сборка проекта и сборка отдельного архива через MCP поддерживают разделение PCK/PKX. Зашифрованные архивы можно читать, извлекать и пересобирать в проекте. Перезапись зашифрованного архива в режиме отдельного файла недоступна.

Поиск по содержимому возвращает до 5000 совпадений и пропускает файлы больше 256 MiB. Для чтения ресурсов в редакторе и упаковки замен также действует лимит 256 MiB на файл. Воспроизведение медиа зависит от кодеков WebView2.
