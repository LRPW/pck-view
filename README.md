## Работа с проектом

1. Нажмите **Создать проект**, укажите папку клиента и выберите архивы для импорта.
2. PW Forge скопирует папку `data` и выбранные PCK/PKX в проект. Манифест `.pwforge` можно открыть из приложения или двойным щелчком после регистрации через **Ассоциация .pwforge**.
3. Открывайте ресурсы в дереве слева. Они появляются во вкладках справа. Записи архивов индексируются, а содержимое извлекается в кэш при открытии файла.
4. Сохранённые правки хранятся отдельно от исходных файлов. Сборка проекта создаёт изменённые PCK и отдельные файлы для переноса в клиент.

Кнопка **Открыть** также позволяет открыть отдельный архив или файл клиента без проекта.

## Формат проекта на диске

```text
MyProject/
  MyProject.pwforge
  originals/
    data/
    archives/
  edits/
    data/
    archives/<архив.pck>/<путь ресурса>
  .forge/
    index/<архив.pck>.json.gz
    cache/
    backups/
  locales/
    source.json
    ru.json
  builds/<идентификатор сборки>/
    pwforge-build.json
```

Манифест представляет собой JSON с `format: "pw-forge-project"` и `version: 2`. Поля `name`, `source`, `archives`, `status` и `errors` описывают имя, исходную папку клиента, выбранные архивы, состояние и ошибки импорта. `bug.pck` исключается. Файлы проекта обслуживаются относительно каталога манифеста.

При чтении приоритет имеет соответствующий файл в `edits/`. Если правки нет, обычный файл читается из `originals/data/`, а ресурс архива извлекается из PCK/PKX. Индекс версии 2 хранит имя, смещение, распакованный и упакованный размеры записей. Сохранённый индекс переиспользуется при совпадении метаданных PCK и PKX. Изменение архива или отсутствие индекса приводит к повторному чтению таблицы записей. Каталоги `.forge/index/` и `.forge/cache/` воспроизводимы из исходных копий.

Сборка принимает сохранённые правки из `edits/`, группирует ресурсы по архивам и создаёт только затронутые PCK и отдельные изменённые файлы. Результат сначала записывается во временный каталог, затем публикуется в `builds/`. В `pwforge-build.json` перечислены собранные архивы и количество отдельных файлов. При необходимости архив проекта разделяется на PCK и PKX.

## Редакторы и поиск

| Формат | Возможности |
| --- | --- |
| PCK / PKX | Дерево ресурсов, извлечение, добавление, замена, удаление и упаковка |
| `elements.data` | Категории, поиск записей, типизированные поля, выбор и предпросмотр ресурсов |
| `gshop.data`, `gshop1.data`, `gshop2.data` | Категории и подкатегории, слоты покупки, иконки инвентаря, переход к предметам и NPC |
| `domain.data`, `domain2.data`, `domain2_cross.data` | Карта, список территорий и подсветка соседей |
| `tasks.data`, `task_npc.data`, `dyn_tasks.data` | Задания, NPC, условия, награды и диалоги |
| Интерфейсы и GFX | Редактирование интерфейсов и нативный предпросмотр GFX |
| Остальные ресурсы | Текст, HEX, изображения, текстуры DDS/TGA, аудио и видео |

Поиск по содержимому открывается в отдельном окне, которое можно перенести на второй монитор. Область поиска можно ограничить проектом, модулем PCK/data или папкой. Есть маска файлов, регулярные выражения, учёт регистра и поиск целых слов. Отмена сохраняет найденные совпадения.

## Перевод

Экспорт текстов создаёт `locales/source.json`. Записи содержат путь к файлу, путь к полю и отдельные фрагменты текста с цветами. Перевод хранится в файле выбранной локали, например `locales/ru.json`.

- В редакторе можно искать текст, показывать только пустые строки и переводить их вручную или пакетно.
- Поддерживаются DeepL, Yandex Translate, Ollama и OpenAI-совместимые API. Ключи сохраняются в Диспетчере учётных данных Windows.
- Пакетный перевод показывает сохранённые результаты по мере обработки. Его можно отменить и продолжить. Заполненные фрагменты сохраняются, а изменения плейсхолдеров и кодов разметки помечаются для ручной проверки.
- **Применить перевод** записывает изменения в файлы проекта через слой правок, сохраняя цвета и исходные файлы.

### Структура JSON

Исходный каталог содержит массив `entries`. Файл перевода также содержит `version` и `language`. В каждой записи `file` задаёт виртуальный путь, `path` указывает поле внутри ресурса, а `segments` содержит фрагменты с `text` и `color`. Цвет записывается как шестизначный RGB без префикса или как `null`. Запись перевода может содержать `source_segments` для сверки с исходным текстом.

Во время пакетного перевода готовые фрагменты записываются в журнал `<язык>.pending.jsonl`. При завершении или следующем запуске пакетного перевода журнал объединяется с JSON локали, заполняя пустые фрагменты. При применении проверяются исходные сегменты и пути полей. Ошибки возвращаются пофайлово.

## Устройство приложения

- `src/app/IdeApp.tsx` управляет деревом, вкладками и открытием ресурсов.
- `src/features/editor/` содержит редакторы, `src/features/search/` — отдельное окно поиска.
- `src-tauri/src/project.rs` отвечает за импорт, индексы, слой правок и сборку проекта. `ide.rs` обслуживает ресурсы и отдельные файлы.
- `src-tauri/src/locales.rs`, `locale_batch.rs` и `translation.rs` отвечают за локали, пакетную обработку и запросы к провайдерам.
- `native-gfx/` содержит отдельный исполняемый компонент. Tauri запускает его для нативного предпросмотра и взаимодействует с ним через бэкенд.

## Установка и сборка

Распакуйте ZIP из [релизов](https://github.com/LRPW/pw-forge/releases) в отдельную папку и запустите `pckview.exe` рядом с `native-gfx.exe` и DLL. Для запуска нужен WebView2 Runtime.

Для сборки нужны Node.js, Yarn Classic, Rust с MSVC, Visual Studio с инструментами C++ x86, Windows SDK и DirectX SDK June 2010. Native GFX также использует исходники и библиотеки движка из дерева клиента, описанные в [native-gfx/README.md](native-gfx/README.md).

Из каталога с `package.json`:

```powershell
yarn install --frozen-lockfile
npm run tauri dev
```

Для выпуска ZIP и контрольной суммы запустите `.\scripts\build-release.ps1`. Результат появится в `release/`. Native GFX собирается автоматически при запуске Tauri в режиме разработки и при сборке релиза.

```powershell
npm test
cargo test --manifest-path src-tauri/Cargo.toml
```

Для интеграционных тестов с реальными файлами задайте `PW_CLIENT_DIR` на папку установленного клиента и запускайте нужный тест с `-- --ignored`.

## Ограничения PCK

Поддерживается формат `0x20002`, включая чтение разделённых архивов PCK/PKX. При сохранении отдельно открытого архива создаётся одиночный PCK размером меньше `0x7fffff00` байт. Сборка проекта поддерживает разделение на PCK и PKX на этой границе. Поиск ограничен 5000 совпадениями и пропускает файлы больше 256 MiB. Зашифрованные архивы доступны для чтения и экспорта. Возможность воспроизведения отдельных медиаформатов зависит от кодеков WebView2.
